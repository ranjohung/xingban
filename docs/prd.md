## 1. 项目概述

### 1.1 产品定位

星伴是一款面向自闭症儿童家长的综合性支持平台，通过AI驱动的行为分析、个性化策略推荐、紧急安抚指导等功能，帮助家长科学应对育儿挑战，建立长期发展规划。

### 1.2 核心价值

- **即时支持**: 在孩子行为问题发生时提供实时指导
- **数据驱动**: 通过记录和分析帮助家长了解孩子发展趋势
- **专业连接**: 连接康复师和家长，建立专业沟通桥梁
- **长期规划**: 帮助家长制定全生涯发展规划

### 1.3 目标用户

- 自闭症儿童家长（核心用户）
- 康复师/特教老师（专业用户）
- 其他照顾者（祖父母、保姆等）

## 2. 市场分析

### 2.1 市场规模

- 全球自闭症患病率约1/68，中国约有超过1000万自闭症人群
- 每年新增确诊儿童约10万+
- 家长对专业支持的需求持续增长

### 2.2 竞争格局

| 竞品 | 优势 | 劣势 |
|------|------|------|
| 传统康复机构 | 专业度高 | 价格昂贵、地域限制 |
| 在线课程平台 | 知识丰富 | 缺乏个性化、互动性弱 |
| 家长社群 | 情感支持 | 信息质量参差不齐 |
| 医疗类App | 专业性强 | 侧重诊断，缺乏日常指导 |

### 2.3 市场机会

- AI技术降低个性化支持门槛
- 移动互联网普及，随时随地获取支持
- 政策支持特殊教育发展

## 4. 产品架构

```
├── 扩展功能区

│   ├── 模块6：家庭系统支持中心

│   └── 模块9：安全与防走失系统
└── 社交功能区
    └── 模块10：同伴联结与孤独感破除
```

### 4.2 用户旅程

```
注册 → 创建儿童档案 → 首次记录 → 获取策略 → 尝试策略 → 反馈效果 → 查看周报 → 分享给康复师
```

### 4.3 零负担交互设计原则

**核心理念**: 特殊儿童家长每天都处于高压力、低精力的状态。所有功能设计必须遵循"零负担"原则——不增加家长的心理负担和操作负担。

**具体规则**:

| 原则 | 说明 | 示例 |
|------|------|------|
| 一句话模式 | 所有功能必须提供"一句话"或"一键"完成的方式 | 行为记录允许只点一个表情就完成，策略反馈允许只点一个emoji就提交 |
| 不催促原则 | 连续3天未记录时，不推送催促通知 | 推送"我们知道你很累，没关系，随时回来" |
| 倦怠检测 | 若用户使用频率骤降（如连续7天未打开），自动切换为"轻量模式" | 首页只展示最核心的"记一笔"和"紧急模式"两个按钮，降低信息负担 |
| 语音唤醒 | 紧急模式下支持语音唤醒（长期规划） | 喊"星伴帮我"即可激活紧急模式，完全解放双手 |
| 正向优先 | 所有反馈以正向为主，避免任何指责性或压力性话术 | 使用"你做得很好"而不是"你应该这样做" |

## 5. 详细功能规格

### 5.0 模块0：儿童数字孪生档案

**功能概述**: 为每个孩子建立多维能力画像，涵盖诊断报告、能力评估、感官偏好、强化物清单、医疗信息等。AI根据档案生成初始干预目标，所有个性化推荐以此为基础。

**核心字段定义**:

| 字段类别 | 字段名 | 类型 | 说明 |
|----------|--------|------|------|
| 基础信息 | 昵称 | String | 必填 |
| 基础信息 | 出生日期 | Date | 必填 |
| 基础信息 | 诊断类型 | Enum | ASD/ADHD/DD/OTHER |
| 能力评估 | 沟通水平 | Enum | 无口语/单词/短语/句子/流畅 |
| 能力评估 | 社交水平 | Int(1-5) | 1=完全无互动，5=主动社交 |
| 能力评估 | 自理水平 | Int(1-5) | 1=完全依赖，5=完全自理 |
| 能力评估 | 认知水平 | Int(1-5) | 1=严重落后，5=同龄水平 |
| 感官特点 | 听觉/视觉/触觉/前庭 | Enum | 敏感/迟钝/寻求/回避/正常 |
| 强化物 | 物品+活动 | JSON数组 | 如["泡泡水","举高高"] |
| 医疗信息 | 过敏/用药 | String | 可选 |

**档案创建向导流程（4步）**:

1. **步骤1：基础信息** — 输入昵称、出生年月、选择诊断类型（ASD/ADHD/DD/OTHER）
2. **步骤2：能力快速评估** — 选择题形式评估沟通、社交、自理、认知四个维度（非标准化量表，降低填写门槛）
3. **步骤3：感官特点** — 多选题选择听觉、视觉、触觉、前庭四方面的特点（敏感/迟钝/寻求/回避/正常）；填写强化物清单（孩子喜欢的物品和活动）
4. **步骤4：完成与初始画像** — 系统生成"初始干预画像"摘要卡片，展示能力雷达图，AI自动生成3条初始干预目标建议

**边界情况**:
- 档案创建过程中可随时保存草稿，72小时内完成
- 诊断类型选择"OTHER"时，需手动输入并说明
- 能力评估数据不足时，使用年龄默认值作为初始模板
- 档案创建后允许随时修改，修改后AI自动更新干预目标建议
- 支持多子女档案（最多绑定3个孩子），切换角色时档案数据隔离

### 5.1 模块1：一键记录与AI结构化

**功能概述**: 支持语音/文字/拍照三种输入方式，AI自动分析行为类型、情绪状态、触发因素，生成结构化记录，并关联历史行为数据形成图谱。

**UX流程**:
1. 首页点击"记录"按钮
2. 选择输入方式：语音/文字/拍照
3. **语音输入**: 长按录音，最长120秒，松手自动上传识别
   - 语音识别失败容错流程：
     - 第1次失败：提示"网络有点慢，请重试"，自动重试一次
     - 第2次失败：提示"识别困难，是否切换文字输入？"，提供语音转文字修正入口
     - 第3次失败：自动切换为文字输入模式，保留音频文件待后续人工处理
4. **文字输入**: 文本框输入，支持字数统计（最多500字）
5. **拍照记录**: 拍摄现场照片，AI辅助识别场景，自动填充情境描述
6. AI自动分析并展示结果：行为类型、情绪状态、触发因素、行为功能、强度等级
7. 确认或编辑分类、标签、备注
8. 保存记录，自动关联历史行为记录，更新行为关联图谱

**行为分类标签体系（27种）**:

| 大类 | 子类 | 说明 |
|------|------|------|
| 情绪爆发 | 尖叫、哭闹、倒地、摔东西 | 情绪失控导致的爆发性行为 |
| 刻板行为 | 摇晃身体、转圈、拍手、排列物品 | 重复性、固定模式的行为 |
| 攻击行为 | 打人、踢人、咬人、抓头发 | 对他人具有攻击性的行为 |
| 自伤行为 | 撞头、咬自己、抓自己 | 对自己造成伤害的行为 |
| 跑开/走失 | 无预警跑开、躲藏 | 突然脱离成人视线范围 |
| 感官寻求 | 过度触摸、盯着光源、闻物品 | 寻求特定感官刺激 |
| 感官回避 | 捂耳朵、遮眼睛、拒绝触碰 | 回避特定感官输入 |
| 沟通尝试 | 用手指、拉人手、发出声音 | 试图表达需求或引起注意 |
| 适应性技能 | 自己穿衣、如厕、吃饭 | 生活自理相关行为 |
| 社交发起 | 主动靠近同伴、分享玩具 | 主动社交互动行为 |
| 进食问题 | 挑食、拒绝进食、进食过快 | 与进食相关的行为问题 |
| 睡眠问题 | 入睡困难、夜醒、早醒 | 与睡眠相关的行为问题 |
| 其他 | 用户自定义 | 不在上述分类中的行为 |

**历史行为关联图谱**:
- 展示同类行为发生的时间分布、触发因素关联、策略效果对比
- 支持按时间轴、行为类型、情绪状态筛选查看
- 点击节点可查看对应记录详情

**边界情况**:
- 无网络时本地暂存音频/图片，有网后自动上传
- 录音超过120秒自动截断并提示
- 放弃记录不保存数据，本地缓存可在24小时内恢复
- 分类可选"其他"，手动输入并提示运营审核后加入分类库

### 5.2 模块2：情景化即时策略推荐

**功能概述**: 基于行为记录和儿童档案，推荐3条个性化策略，包含步骤、话术、原理，支持反馈学习。

**UX流程**:
1. 记录保存后自动展示策略，也可从首页"获取策略"入口主动查询
2. 显示3张策略卡片，每张包含：名称、图标、适用说明、折叠的步骤/话术，喇叭朗读
3. 卡片底部："试过了吗？效果如何→" 点击展开表情反馈（😊有效/😐一般/😞无效）+选填笔记
4. 连续3次反馈无效，切换为共情模式，提供紧急模式跳转
5. 排序逻辑：历史最有效 → 最简单 → 进阶策略

**技能泛化追踪**:

场景：家长在餐桌场景学会了策略A，但不知道是否适用于超市、学校等其他场景。

- 当某个策略在特定场景被标记为"有效"超过3次后，系统自动提示："该策略在餐桌场景效果良好，是否尝试在以下场景使用？"
- 系统推荐2-3个相似场景（基于场景相似度算法）
- 推荐场景示例：餐桌 → 超市收银台、学校食堂、家庭聚餐
- 家长可选择"去试试"或"暂不尝试"
- 尝试新场景后，系统追踪策略在新场景的效果

**场景相似度匹配规则**:

| 原始场景 | 相似场景推荐 | 匹配理由 |
|----------|--------------|----------|
| 餐桌吃饭 | 超市收银台 | 涉及等待、规则遵守 |
| 餐桌吃饭 | 学校食堂 | 涉及集体用餐、社交互动 |
| 客厅游戏 | 公园玩耍 | 涉及社交互动、规则遵守 |
| 客厅游戏 | 教室课堂 | 涉及轮流、注意力维持 |
| 卧室睡前 | 午睡时间 | 涉及作息规律、情绪调节 |

**行为功能分析教学引导**:

当AI输出行为功能假设时（如"逃避型行为""求关注行为"），每条假设旁显示一个问号图标，点击后弹出教学卡片，用通俗语言解释专业术语：

| 功能类型 | 通俗解释 | 常见表现 |
|----------|----------|----------|
| 逃避型行为 | 孩子在说"我不想做这个" | 任务太难、时间太长、环境不适应时出现 |
| 求关注行为 | 孩子在说"看看我" | 即使被批评也是关注，孩子会重复做 |
| 感官刺激行为 | 孩子在说"我的身体需要这个感觉" | 摇晃、拍手、转圈等自我刺激行为 |
| 获取实物行为 | 孩子在说"我想要那个" | 通过哭闹、抢夺等方式获取喜欢的物品或活动 |

教学卡片设计：
- **标题**: "什么是逃避型行为？"
- **内容**: "孩子可能用这个行为来逃避不喜欢的任务。例如，不想洗澡所以尖叫。当任务太难或孩子疲惫时更常见。"
- 配简笔画风格插画（示意场景）
- 卡片底部提供"了解更多"链接，跳转家长学院相关课程

**干预一致性检查**:

系统检测到当前全生涯目标与推荐策略方向不一致时，在策略卡片顶部显示一致性提示卡片：

- 检测逻辑：将当前活跃目标的关键词（如"增加社交发起"）与策略方向标签（如"减少社交回避"）进行语义匹配
- 发现不一致时提示："该策略主要针对减少社交回避，而您当前的目标是增加主动社交发起。是否同时查看主动社交相关的策略？"
- 提供"查看相关策略"按钮，点击后展示方向一致的策略列表
- 此功能避免家长在不同方向间摇摆，浪费干预精力

**边界情况**:
- 档案不完整时使用默认年龄/诊断模板
- 策略库覆盖不足时记录日志，运营补充
- 朗读话术TTS语速0.8x，语气温和

### 5.3 模块3：紧急安抚模式

**功能概述**: 在孩子情绪崩溃时提供零思考引导界面，先稳定家长情绪，再逐步给出安抚策略，支持桌面小组件和智能手表联动。

**UX流程**:
1. **触发方式**:
   - App内"SOS"暖橙色按钮（底部固定）
   - **PWA快捷方式**: 添加到主屏幕的快捷图标，一键打开紧急模式（替代原生桌面小组件）
   - **锁屏通知快捷操作**: 紧急通知推送时，支持锁屏直接点击进入紧急模式
   - **智能手表联动**: 通过HealthKit/Google Fit读取心率（MVP降级方案）
   - **系统级快捷方式**: iOS快捷指令、Android快捷方式

**桌面小组件说明**: Web应用无法实现原生Widget（如iOS WidgetKit），故MVP阶段使用以下替代方案：

| 方案 | 实现方式 | 效果 |
|------|----------|------|
| PWA快捷方式 | 添加到主屏幕 | 点击图标直接进入紧急模式 |
| 锁屏快捷操作 | 通知推送时显示操作按钮 | 锁屏状态下一键触发 |
| 系统快捷方式 | iOS快捷指令/Android快捷方式 | 语音或手势触发 |

**P3远期规划**: 通过Capacitor打包原生壳，实现真正的桌面小组件。
2. 进入界面：全屏深蓝灰背景，第一屏"先深呼吸一次"+呼吸动画（4秒扩/4秒缩，轻微震动）
3. **分级响应选择**（深呼吸动画之后）：
   - 显示快速选择页面："当前情况属于："
   - 🟢 **一般行为问题** — 如哭闹、拒绝配合、发脾气
   - 🟡 **情绪爆发升级** — 如尖叫、摔东西、打滚
   - 🔴 **有伤害风险** — 如自伤行为（撞头、咬自己）、攻击他人
   - 选择不同级别后差异化响应：
     - 🟢：以常规安抚策略为主（当前设计）
     - 🟡：增加降级策略和感官调节工具，策略更注重情绪降温
     - 🔴：优先包含安全处置指引，自动附带紧急求助信息（附近医院、派出所位置）
4. 3秒后自动展示第一条安抚策略（大字），每15秒轮播下一条，可手动滑动切换
5. **路人管理话术**: 提供应对周围路人围观的话术模板，如：
   - "孩子现在需要安静，请不要拍照，谢谢理解"
   - "孩子有特殊需求，我们正在处理，请保持距离"
6. 退出：点击"结束"或10分钟无操作自动退出，保存会话

**紧急模式退出后的立即反馈**:

当前设计是退出后30分钟推送回访。需在退出瞬间增加即时反馈：
- 退出紧急模式后，不立即显示回顾表单
- 第一屏显示简短的正向肯定文字："刚才的情况很艰难，但你撑过来了。你做得足够好。"
- 3秒后自动消失，或点击"我知道了"关闭
- 提供一键跳转"能量加油站"的入口

**30分钟后的回访优化**:

增加"此刻的感受"选择：😌已平静 / 😔还在低落 / 😤依然愤怒
- 选择"😌已平静"才展开回顾表单
- 选择"😔还在低落"或"😤依然愤怒"时，推送心理支持内容或一键跳转"能量加油站"

**能量加油站**:

一个小角落，位于"我的"页面：
- 收藏所有"微光时刻"、里程碑成就、正向反馈
- 紧急模式结束后可一键跳转至此
- 目的：让家长在被挫败感淹没时，能快速重拾信心

**感谢卡收藏规则**（隐私边界）:
- 感谢卡默认**不自动**进入能量加油站
- 家长可选择将某张已发送的感谢卡手动"收藏到加油站"
- 收藏操作**对配偶不可见**，仅家长本人可查看

**温柔回访提醒**: 退出后30分钟推送温和通知，引导简短的回顾表单（最多提醒2次）

**智能手表联动（MVP阶段降级方案）**:

**MVP阶段实现方式**: 通过 HealthKit（iOS）/ Google Fit（Android）API 读取家长心率数据，用于判断家长情绪状态，不开发独立手表App。

| 功能 | MVP实现 | 说明 |
|------|---------|------|
| 心率读取 | 读取家长静息心率 | 通过系统健康API获取，用于情绪评估 |
| 情绪预警 | 心率异常时提醒 | 心率超过阈值时，建议家长先进行深呼吸 |
| 紧急模式触发 | 手机端触发 | 不支持手表端一键触发（P3规划） |
| 策略同步 | 手机端查看 | 不支持手表端显示策略（P3规划） |

**P3远期规划**: 开发独立智能手表App，支持一键触发紧急模式、振动提醒策略切换。

**边界情况**:
- 完全离线可用，紧急策略预缓存到本地
- 紧急模式中来电处理，通话结束后返回当前策略页
- 事后回顾最多提醒2次，超过则不再打扰
- 健康数据读取失败时，不影响核心功能使用

**预防性预警（V2规划）**:

- 系统基于历史行为数据，识别高风险时段和场景
- 在高风险时段前30分钟推送预警通知
- 预警内容示例：
  - "根据历史记录，周一早晨通常是情绪爆发高发时段。建议提前10分钟预告活动转换。"
  - "今天下午有雷雨天气，历史上孩子在天气变化时容易焦虑。准备好感官安抚物品。"
- 家长点击预警可直接进入预防策略页面
- 预防性预警开关默认关闭，用户可在设置中开启

**实时协作支援（V3规划）**:

- 紧急模式下提供"邀请支援"按钮，位于策略页面右上角
- 可向预设的紧急联系人或当前在线康复师发送支援请求
- 支援者收到通知后，可查看当前紧急模式的策略和历史行为摘要（需获得家长授权）
- 支援者可通过文字或语音提供实时建议
- 支援会话全程加密，结束后自动关闭共享权限

### 5.4 模块4：康复师沟通周报自动生成

**功能概述**: 每周自动汇总行为记录、策略效果，生成图文周报，支持分享给康复师并在线评论，康复师可免注册通过H5查看。

**UX流程**:
1. 每周六晚20:00生成周报（可自定义生成时间），推送通知
2. 周报展示：趋势箭头、环形图、时间线、策略排行榜、AI评语、"家长最关心的3个问题"
3. **一键分享**: 生成微信/H5分享链接，康复师免注册查看
   - 康复师打开链接后，可对任意段落评论，评论自动同步回家长App
   - 家长可回复康复师评论，形成双向沟通
4. **康复师专业版**:
   - 学员管理看板：查看所有学员周报、筛选、排序
   - 长期趋势图：跨周对比、月度/季度统计
   - AI干预建议：基于学员数据自动生成干预方案建议
   - 个人品牌主页：展示专业背景、擅长领域、家长好评

**康复师激励机制**:

**问题**: 康复师本身工作超负荷，需要设计激励让他们愿意花时间在平台上互动。

**激励措施**:

| 激励方式 | 说明 | 实现方式 |
|----------|------|----------|
| 收入挂钩 | 与康复机构合作，将平台使用情况纳入机构内部绩效考核参考 | 提供机构管理后台，展示康复师在平台的周报查看率、家庭作业批阅率、家长满意度 |
| 继续教育学分 | 与省级康复协会或中国残联合作，完成培训课程、督导记录可获得官方认可的继续教育学分 | 与专业机构合作开发认证课程，完成后自动发放电子学分证书 |
| 个人品牌展示 | 康复师可在平台展示专业背景、擅长领域、家长好评，吸引更多家长选择其服务 | 建立类似医生在线平台的评价体系，形成正向循环 |

**家长评价体系**:
- 家长可对康复师的评论和建议进行"有帮助/一般/无帮助"评价
- 评价数据汇总为康复师的"专业评分"和"满意度"指标
- 评价内容脱敏展示，保护双方隐私

**康复师专业评分计算**:
- 基础分：100分
- 加分项：周报查看率(+10分/周)、评论回复及时率(+5分/次)、家长好评率(+15分/月)
- 减分项：连续2周未查看周报(-10分)、家长投诉(-20分/次)

**康复师排名**:
- 平台内康复师按专业评分排名
- 排名靠前的康复师获得"星伴认证专家"标识
- 认证专家优先推荐给家长用户

**康复师免注册H5查看**:
- 分享链接包含加密Token，有效期30天
- H5页面支持查看周报全文、评论、点赞
- 康复师可选择注册账号，关联家长分享的所有周报

**评论双向同步**:
- 康复师在H5评论 → 家长App收到通知 → 家长回复 → 康复师H5收到通知
- 评论支持@提及、表情、图片
- 评论历史按时间线展示

**异步视频反馈闭环**:

完整闭环流程：

1. **家长上传视频**: 在记录详情页选择"上传视频"，拍摄/上传一段干预实操视频（最长3分钟），上传时自动压缩至720p以内
2. **视频随周报分享**: 视频作为周报附件，随分享链接一起发送给康复师
3. **康复师时间轴标注**: 康复师在H5查看页播放视频，可在时间轴上添加标注（如"00:32-00:45 这里辅助等级过低"），标注点以标记显示在进度条上
4. **康复师评论**: 康复师添加语音/文字评论，评论与视频时间轴关联
5. **家长查看反馈**: 家长App收到通知，查看视频标注和评论，标记"已理解"或"有疑问"
6. **系统记录**: 每次视频督导互动被记录，下次周报自动体现"本月完成X次视频督导"

**边界情况**:
- 视频上传失败时自动重试，最多3次
- 视频格式仅支持 mp4/mov，大小超过100MB提示压缩
- 康复师标注不可删除家长原始视频，仅可编辑自己的标注
- 视频存储有效期90天，到期前7天通知双方下载

**周报"未来一周预测"板块**:

在周报结构中增加"下一周关注"板块：

- 基于过去4周行为趋势，AI分析预测下周可能的高风险时段和场景
- 推送1-2条预防性建议，例如：
  - "根据历史数据，周一早晨是情绪爆发高发时段，建议提前10分钟预告活动转换"
  - "上周三在超市出现两次行为问题，建议本周三前往超市前先做视觉提示"
- 预测置信度标注（高/中/低），让家长了解推荐的可靠程度
- 该板块位于周报末尾，作为"本周回顾→下周关注"的自然过渡

**边界情况**:
- 记录过少(<3条)时显示简化报告，仅包含基础统计
- 分享链接有效期30天，家长可手动延长或撤销
- 康复师评论不可删除家长原始数据，仅可编辑自己的评论
- 周报生成失败时，发送重试通知，最多重试3次

### 5.5 模块5：全生涯规划与未来模拟器

**功能概述**: 帮助家长了解各阶段发展里程碑，设置和追踪目标，提供未来场景模拟和法律/财务规划指引。

**UX流程**:
1. 生涯时间轴：横向滑动，阶段：刚确诊→早期干预→学前→学龄→青春期→青年→成年
2. 里程碑为可点亮的星星，点击记录达成故事，支持上传照片/视频
3. 目标设定：选择领域（社交、生活自理、学习、职业），AI分解为10-20个子步骤，进度条可视化
4. **未来模拟器**:
   - 输入能力评估（当前能力水平、支持程度）
   - 展示三种支持水平下的未来生活场景：
     - **基础支持（家庭支持为主）**: 描述家庭环境下的生活自理、社交互动、职业可能性
     - **中等支持（社区+机构支持）**: 描述社区资源利用、日间照料、庇护性就业
     - **全面支持（专业团队+政策支持）**: 描述专业团队干预、政策保障、独立生活
   - 每种场景附带真实案例故事链接，增加可信度
5. **法律规划渐进式对话引导**:
   - 第一步（降低心理门槛）："如果发生意外，你希望谁临时照顾孩子？"
   - 第二步："你是否已经指定了法定监护人？"
   - 第三步："你是否考虑过孩子成年后的监护安排？"
   - 第四步："你是否了解特殊教育相关的法律权益？"
   - 每步回答后提供相关法律知识链接

**边界情况**:
- 未来模拟器强制免责声明，明确说明模拟仅供参考
- 法律部分仅提供信息指引，不构成正式法律建议
- 目标分解失败时，提供默认目标模板
- 里程碑数据缺失时，显示通用里程碑建议

### 5.6 模块6：家庭系统支持中心

**功能概述**: 照顾者心理健康支持、配偶感谢卡AI生成、隔代沟通三种话术模板、手足专属时光活动推荐。

**UX流程**:
1. **情绪签到**: 每日表情选择（5种情绪：平静、开心、疲惫、焦虑、低落），连续低落触发共情消息和正念引导
2. **配偶感谢卡AI生成**:
   - 每周五推送感谢卡生成提醒
   - AI基于近期家庭互动记录生成3个版本草稿：
     - **温情简洁版**（50字以内）：适合日常感谢
     - **具体细节版**（80字左右）：包含具体事例
     - **幽默轻松版**（60字左右）：带点幽默的感谢
   - 用户可编辑、保存或分享给配偶
3. **隔代沟通三种话术模板**:
   - 输入场景描述（如"爷爷总是给孩子买糖果"）
   - AI输出三种风格回应：
     - **温和说服型**: 以理解和共情为主，如"我理解您想让孩子开心，不过医生建议控制糖分摄入"
     - **科普教育型**: 提供专业知识支撑，如"根据自闭症干预原则，规律的饮食习惯对孩子更重要"
     - **边界设定型**: 明确界限和原则，如"为了孩子的健康，我们约定每周最多吃两次糖果"
4. **手足专属时光活动推荐**:
   - 每月提醒一次，推荐基于年龄的互动活动
   - 活动建议包含：亲子游戏、手工制作、户外探索、阅读时光
   - 支持记录活动完成情况，生成"手足时光"相册
5. **CBT思维记录**: 引导完成5步流程（情境→想法→情绪→证据→替代想法），支持分步自动保存

**边界情况**:
- 情绪连续低落7天，推送心理援助热线
- 家庭模块内容仅本人可见，配偶需通过分享链接查看感谢卡
- 感谢卡生成失败时，使用通用模板
- 隔代沟通话术生成失败时，提供默认话术模板

### 5.7 模块7：家长成长体系 (Parent Growth System)

**功能概述**: 建立统一的家长能力成长追踪体系，通过干预能力指数衡量家长在育儿过程中的硬实力提升，同时记录活跃度和学习投入，通过数据反馈增强家长信心和留存。

**核心设计原则**:
- 只对外展示一套评分体系："干预能力指数"
- 学习时长、周报查看率、分享互动等作为辅助参考维度，不单独成体系
- 统一展示出口：家长端只有一个"我的成长"仪表盘

**干预能力指数 (Intervention Capability Index)**:

| 维度 | 权重 | 计算方式 | 说明 |
|------|------|----------|------|
| 策略使用频率 | 25% | 近30天使用策略次数 / 目标15次 | 频率越高越好 |
| 策略成功率 | 25% | 策略反馈为"有效"的比例 | 正向反馈权重更高 |
| 情绪调节能力 | 20% | 使用深呼吸等情绪调节工具的次数 | 家长自身情绪管理 |
| 记录习惯 | 15% | 近30天记录天数 / 30 | 连续记录更重要 |
| 学习活跃度 | 15% | 阅读文章、完成课程的数量 | 主动学习加分 |

**辅助参考维度（不纳入主评分，展示在雷达图上）**:

| 维度 | 计算方式 | 说明 |
|------|----------|------|
| 周报查看率 | 近4周查看周报次数 / 4 | 反映家长对孩子成长的关注程度 |
| 分享互动次数 | 分享周报/策略给康复师的次数 | 反映家长与专业团队的协作意愿 |

**能力等级体系**:

| 等级 | 名称 | 分数范围 | 描述 |
|------|------|----------|------|
| L1 | 新手家长 | 0-30 | 刚刚开始学习，需要更多指导 |
| L2 | 成长家长 | 31-60 | 开始掌握基本干预方法 |
| L3 | 熟练家长 | 61-80 | 能够独立应对常见行为问题 |
| L4 | 专业家长 | 81-95 | 具备专业干预能力 |
| L5 | 专家家长 | 96-100 | 可指导其他家长 |

**成长可视化——"成长树"设计**:

不再使用冷冰冰的数字仪表盘，而是用一棵树的生长来映射家长的成长历程：
- 每解锁一项新技能（如"首次使用视觉提示卡成功""连续7天记录行为"），树上长出一片新叶
- 每达到一个新等级，树上开出一朵花
- 长期来看，一棵枝繁叶茂、花朵盛开的大树，是对家长自我效能感的巨大支撑
- 点击树叶可查看对应成就的详情

**反馈体系层级关系**:

微光时刻、周报家长反馈、月度干预小结三者数据来源相同（都是干预能力指数各维度），但展示颗粒度不同，开发时使用同一数据服务层。

| 反馈类型 | 推送时机 | 内容特点 | 展示形式 | 数据颗粒度 |
|----------|----------|----------|----------|------------|
| 微光时刻 | 当天发生有效策略反馈或连续3天记录 | 即时性、轻量 | 精美插画+一句话温暖文案 | 单条事件 |
| 周报家长反馈 | 每周六周报生成时 | 每周汇总 | 嵌入周报"家长成长"板块 | 7天数据 |
| 月度干预小结 | 每月1日上午10:00 | 深度回顾 | 独立推送温馨卡片 | 30天整体趋势 |

**数据一致性保障**:
- 三者共用同一 `ParentGrowthService` 数据服务层
- 干预能力指数计算逻辑统一，避免重复计算
- 微光时刻数据自动汇总进入周报和月度小结
- 所有反馈内容基于同一数据源，确保数值一致

**微光时刻推送**:

当系统检测到一次有效策略反馈、或连续3天坚持记录时，推送一张"微光卡"：
- 微光卡内容：精美插画 + 一句温暖文案（如："你今天的坚持，是孩子明天的一束光"）
- 微光卡可收藏，在"能量加油站"中随时查看

**能量加油站**:

一个小角落，位于"我的"页面：
- 收藏所有"微光时刻"、里程碑成就、正向反馈
- 紧急模式结束后可一键跳转至此
- 目的：让家长在被挫败感淹没时，能快速重拾信心

## 6. AI可靠性保障体系

**核心定位**: 确保星伴不仅仅是"豆包式"AI玩具，而是具备专业可信度的AI辅助工具。所有AI输出必须可追溯、可校验、可问责。

### 6.1 第一层：结构化知识库约束

**设计原则**: AI的职责是"理解和匹配"，而非"发明策略"。

- 所有策略推荐必须来自预先编写、专家审核的 `Strategy` 表
- AI的行为是对用户输入进行语义理解，在知识库中匹配最合适的策略
- 当AI无法在知识库中找到匹配项时，不强行生成，而是诚实反馈：
  - "针对此情况，暂无匹配策略，已记录为待补充场景，建议咨询您的康复师。"
- 策略推荐API的响应必须包含 `source` 字段，注明：
  - 策略来自知识库具体条目编号（如 `STR-2026-0342`）
  - 审核专家姓名（如 `审核专家：张敏（BCBA）`）
- 策略库更新需经过三审流程：编辑初审 → 专家复审 → 总编终审

**AI模型降级策略**:

| 优先级 | 模型 | 适用场景 | 切换条件 |
|--------|------|----------|----------|
| P0 | DeepSeek（主力） | 全部AI调用 | 默认 |
| P1 | 备用模型A（如GPT-4o-mini合规代理） | 行为分析、策略推荐 | DeepSeek超时或连续失败3次 |
| P2 | 本地规则引擎 | 行为分类、简单匹配 | 所有云端模型不可用 |
| P3 | 静态兜底话术 | 全部场景 | 完全离线或全部服务不可用 |

降级时前端展示提示："AI服务暂时繁忙，已为您切换至基础模式。"

### 6.2 第二层：多模型交叉校验（高危场景）

**适用范围**: 以下高风险场景必须进行交叉校验

- 行为记录包含"自伤""攻击他人""窒息""吞食"等关键词
- 家长情绪连续标记为"极度低落"超过3天
- 紧急模式中标记为🔴级别（有伤害风险）

**校验流程**:

1. 同一输入同时发送给两个不同的AI模型（主模型 + 校验模型）
2. 只有当两者的行为分类和策略方向一致时，才正常输出
3. 若出现分歧，自动降级为安全兜底话术，并标记为"需人工复核"
4. 人工复核结果用于持续优化模型对账逻辑

**安全兜底话术**:
- "当前情况需要更专业的判断，请优先联系您的康复师或拨打希望24热线：400-161-9995"
- 话术中不包含任何具体策略建议，仅引导寻求专业帮助

### 6.3 第三层：输出内容安全护栏

**安全过滤器**: 所有AI生成的文本在返回前端之前，必须经过 `SafetyFilterService`

**拦截内容**:
| 拦截类别 | 示例 | 检测方式 |
|----------|------|----------|
| 体罚相关 | "打一顿就好了""关禁闭" | 关键词正则匹配 |
| 药物建议 | "建议服用XX药物""加大剂量" | 关键词正则匹配 + 语义理解 |
| 未经证实的疗法 | "高压氧舱""干细胞治疗" | 关键词正则匹配 |
| 对家长的负面评价 | "你做得不对""你太溺爱了" | 语义理解模型 |
| 鼓励放弃治疗 | "别治了""没希望了" | 语义理解模型 |
| 孤立儿童暗示 | "别让孩子出门""藏在家里" | 语义理解模型 |

**实现方式**:
- 第一道防线：关键词正则匹配（低延迟，拦截率~80%）
- 第二道防线：轻量级语义理解模型（延迟<200ms，拦截率提升至~95%）
- 两道防线均通过后，内容才可返回前端
- 被拦截的内容记录日志，每周汇总分析，持续优化匹配规则

### 6.4 第四层：用户反馈闭环与策略动态权重

**策略权重动态调整**:

- 每条策略维护一个 `effectiveness_weight` 字段（初始值1.0，范围0-1.0）
- 家长标记为"无效"的策略，对该儿童的推荐权重立即降低（权重 × 0.8）
- 某策略被全局标记"无效"比例超过30%，自动触发人工复核通知
- 被多次标记为"危险"的策略，立即从推荐池中下架，并通知运营团队

**数据模型**:

```sql
-- 策略权重表（strategy_weights）
strategy_id    UUID       -- 关联策略ID
child_id       UUID       -- 关联儿童（NULL=全局权重）
weight         FLOAT      -- 当前权重（0.0-1.0）
invalid_count  INT        -- 无效反馈次数
danger_count   INT        -- 危险反馈次数
last_updated   TIMESTAMP  -- 最后更新时间
```

### 6.5 第五层：人机协作的兜底机制

**触发条件**: 以下高风险场景自动触发人工兜底

1. 孩子出现自伤行为（撞头、咬自己、抓伤等）
2. 孩子出现攻击他人行为
3. 家长情绪评分连续7天处于"极度低落"
4. 家长在任意文本输入中使用了高危关键词（自杀、自残、放弃等）

**响应机制**: 此时系统不提供AI建议，而是输出具体的行动指引：

- **城市儿童心理急诊医院列表**: "您所在城市的儿童心理急诊医院：XX市儿童医院（地址：XX路XX号，电话：XXX-XXXXXXX）"
- **附近派出所位置**: 基于用户定位，显示最近的3个派出所/警务站位置
- **紧急求助热线**:
  - 希望24热线：400-161-9995（24小时）
  - 全国心理援助热线：12320-5
  - 本地110/120

**话术要求**:
- 不使用"建议你去看医生"等敷衍话术
- 使用具体、可执行的行动指引，包括地址、电话、路线
- 话术语气保持温暖共情，不给家长增加负罪感

## 9. 全局设计

### 9.1 用户引导

- **7天新手引导计划**: 从创建档案、首次记录、获取策略、数据看板、家庭系统到同伴社区，每日任务+勋章激励
- **勋章体系**: "勇敢的开始""行动派""记录达人""策略高手"等

### 9.2 可访问性设计

- 最小字号16sp，支持系统字体缩放
- 对比度≥WCAG AA标准（4.5:1）
- 所有文本输入框支持语音输入
- 触控目标≥48x48dp，间距≥8dp
- 紧急模式禁用闪烁动画；全局动画可关闭
- 支持TalkBack/VoiceOver语义化标签

### 9.3 智能推送规则引擎

**核心设计原则**: 所有推送逻辑集中管理，业务代码只负责写入任务，由定时任务统一消费。

**核心推送规则表**:

| 推送场景 | 触发条件 | 推送内容 | 免打扰时段 | 重复逻辑 |
|----------|----------|----------|------------|----------|
| 温柔回访 | 紧急模式结束且用户未手动填写回顾表单 | "刚才的情况，要简单回顾一下吗？" | 22:00-08:00不推送 | 30分钟后第1次，24小时后第2次，再未响应则关闭 |
| 情绪援助 | 情绪签到连续7天为"低落" | 共情文字 + 心理援助热线入口 | 无免打扰 | 7天内不重复推送 |
| 周报生成 | 每周六晚20:00系统定时任务完成 | "{孩子姓名}的成长周报已生成，点击查看" | 20:00准时推送 | 仅推送1次 |
| 微光时刻 | 有效策略反馈或连续3天记录 | 精美插画 + 温暖文案 | 22:00-08:00不推送 | 每天最多1条 |
| 月度小结 | 每月1日上午10:00 | "上个月你坚持了X天，来看看成果" | 10:00准时推送 | 仅推送1次 |
| 补贴到期提醒 | 用户关注的补贴申请截止日期前7天 | "XX补贴申请即将截止，点击查看所需材料" | 10:00-20:00推送 | 截止前7天、3天、1天各1次 |
| 倦怠关怀 | 连续7天未打开App | "我们知道你很累，没关系，随时回来" | 10:00-18:00推送 | 7天1次，超过30天未打开则暂停 |

**技术实现**:

- 后端使用 `scheduled_notifications` 表管理所有待推送任务
- 定时任务（Cron Job）每分钟扫描一次待推送任务
- 推送渠道优先级：App内推送 > Web Push > 短信（仅关键场景）
- Web Push不可达时，降级为短信提醒（仅限"温柔回访""情绪援助"等关键场景）

**边界情况**:
- 用户可在设置中关闭特定类型的推送
- 免打扰时段内的推送自动延迟至次日10:00
- 连续3次推送未互动，自动降低该类型推送频率

**周报推送失败降级策略**:
- 周报生成后24小时内用户未查看，次日12:00补推一次
- 超过48小时未查看则不再推送，用户可在App内手动查看周报入口
- 补推时推送内容调整为："上周{孩子姓名}的成长周报还没看哦，点击查看"
- 补推不占用当周其他推送额度

### 9.4 数据权限矩阵

**权限模型设计**: 基于角色的数据权限控制，所有跨用户数据访问统一通过 `PermissionService` 鉴权。

**角色定义**:

| 角色 | 说明 | 典型用户 |
|------|------|----------|
| parent | 家长本人 | 孩子的父母 |
| therapist | 康复师（已授权） | 与家长建立服务关系的康复师 |
| trusted_contact | 信任联系人 | 家长设置的紧急联系人 |
| other | 其他用户 | 未授权的普通用户 |

**数据权限矩阵**:

| 数据类型 | 家长本人 | 康复师（已授权） | 信任联系人 | 其他用户 |
|----------|----------|-----------------|------------|----------|
| 行为记录 | 读/写 | 读（仅已分享的周报汇总） | 无权限 | 无权限 |
| 儿童档案 | 读/写 | 读（需家长主动分享） | 无权限 | 无权限 |
| 安全身份卡 | 读/写 | 读（需设为信任联系人） | 读（需设为信任联系人） | 无权限 |
| 家长成长指数 | 读 | 读（需家长主动开启分享开关） | 无权限 | 无权限 |
| 干预策略 | 读/写 | 读（仅已分享的策略） | 无权限 | 无权限 |
| 周报 | 读/写 | 读（需分享链接） | 无权限 | 无权限（分享链接除外） |
| 感谢卡 | 读/写 | 无权限 | 无权限 | 无权限 |
| 财务记录 | 读/写 | 无权限 | 无权限 | 无权限 |
| 生涯规划 | 读/写 | 读（需家长主动分享） | 无权限 | 无权限 |

**授权机制**:

| 授权类型 | 授权方式 | 有效期 | 撤销方式 |
|----------|----------|--------|----------|
| 康复师访问周报 | 家长生成分享链接 | 30天 | 家长手动撤销 |
| 康复师访问成长数据 | 家长在设置中开启开关 | 持续有效 | 家长关闭开关 |
| 信任联系人访问身份卡 | 家长在安全设置中添加 | 持续有效 | 家长移除信任联系人 |

**权限实现**:

- 所有API在访问其他用户数据前，必须调用 `PermissionService.verify(requestUserId, targetUserId, dataType, action)`
- 权限检查逻辑：数据所有者 > 授权列表 > 角色默认权限
- 家长可随时在"隐私设置"中撤销对特定康复师或联系人的授权
- 授权变更实时生效，已分享但未查看的内容自动失效

**安全原则**:
- **最小权限原则**: 每个角色只能访问完成工作所需的最小数据集合
- **明确授权**: 所有跨用户访问必须有明确的授权记录
- **审计日志**: 所有权限检查操作记录审计日志
- **即时撤销**: 家长可随时撤销已授予的权限，立即生效

### 9.5 推送失败降级策略与多渠道分发

**核心原则**: 推送不得成为用户负担，失败时必须优雅降级，不可重复打扰。

**推送渠道优先级**:

| 优先级 | 渠道 | 适用场景 | 失败降级 |
|--------|------|----------|----------|
| P0 | App内推送 | 全部场景 | 降级为Web Push |
| P1 | Web Push（浏览器推送） | 温柔回访、情绪援助、周报生成 | 降级为短信（仅关键场景） |
| P2 | 短信 | 温柔回访、情绪援助、走失紧急模式 | 不再推送，记录日志 |

**各场景降级策略**:

| 推送场景 | 降级条件 | 降级动作 | 最终兜底 |
|----------|----------|----------|----------|
| 周报生成 | 生成后24小时未查看 | 次日12:00补推一次，文案调整为"还没看哦" | 超过48小时不再推送，用户可在App内手动查看 |
| 温柔回访 | 紧急模式结束30分钟后 | 推送首次温柔回访 | 24小时后第2次，再未响应则关闭 |
| 情绪援助 | 情绪签到连续7天低落 | 推送共情文字+心理援助热线 | 7天内不重复推送 |
| 微光时刻 | 有效策略反馈或连续3天记录 | 推送精美插画+温暖文案 | 每天最多1条，22:00-08:00不推送 |
| 倦怠关怀 | 连续7天未打开App | 推送"我们知道你很累，没关系" | 7天1次，超过30天未打开则暂停推送 |
| 补贴到期提醒 | 截止前7天 | 推送提醒 | 截止前7天、3天、1天各1次 |
| 走失紧急模式 | 触发后立即 | 自动向所有信任联系人推送 | 持续推送直到用户取消 |

**状态管理**:
- 所有推送任务统一写入 `scheduled_notifications` 表
- 定时任务每分钟扫描一次待推送任务
- 推送状态：pending → sent → opened / failed → 降级处理
- 连续3次推送未互动，自动降低该类型推送频率
- 用户可在设置中关闭特定类型的推送
- 免打扰时段（22:00-08:00）内的推送自动延迟至次日10:00

## 附录7-A：成长树触发事件清单

### 一、设计理念

成长树是家长能力成长的可视化隐喻。树的生长状态直接映射家长在平台上的投入和进步：

- **树苗阶段（L1-L2）**：细小但顽强，象征新手家长的起步
- **成长阶段（L2-L3）**：枝叶渐密，象征家长开始掌握方法
- **繁茂阶段（L3-L4）**：枝繁叶茂，象征家长能独立应对常见问题
- **开花阶段（L4-L5）**：花朵绽放，象征家长已成为专家

**核心设计原则**：

1. 只奖励正向行为，不惩罚不活跃
2. 树叶一旦生长就永久保留，不会因不活跃而掉落
3. 同一触发事件不可重复触发（除非特别标注）
4. 所有视觉变化需配合微动画（0.3-0.5秒缓动），不可生硬闪现

### 三、技术实现要点

#### 3.1 事件触发流程

```
用户行为发生 → 业务逻辑层判断是否满足触发条件
→ 写入 growth_tree_events 表 → 返回事件ID
→ 前端收到事件后播放对应动画 → 动画结束后更新成长树状态
```

#### 3.2 数据模型

**成长树事件记录表（growth_tree_events）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 事件唯一ID |
| user_id | FK | 关联用户 |
| event_code | VARCHAR(10) | 事件编号（如E-001） |
| event_name | VARCHAR(50) | 事件名称 |
| event_category | ENUM | 事件类别：milestone/streak/level_up/learning/community/special |
| trigger_data | JSON | 触发时的上下文数据（如当前等级、连续天数） |
| is_first_time | BOOLEAN | 是否首次触发（用于不可重复事件） |
| animation_played | BOOLEAN | 动画是否已播放 |
| created_at | TIMESTAMP | 触发时间 |

#### 3.3 展示优先级规则

当多个事件同时触发时（如：连续7天达成 + 等级提升同时发生），按以下优先级展示：

1. **等级跃升类（E-201至E-204）**——最高优先级，立即播放
2. **持续坚持类（E-101至E-105）**——次优先级
3. **特殊纪念类（E-501至E-504）**——第三优先级
4. **里程碑事件（E-001至E-008）**——第四优先级
5. **学习成长类（E-301至E-303）**——第五优先级
6. **社区贡献类（E-401至E-403）**——第六优先级

同一优先级内的事件按触发时间先后排队播放，每个动画之间间隔0.5秒。

#### 3.4 性能要求

- 成长树使用CSS动画或Lottie实现，不得使用GIF（体积过大）
- 所有动画素材需预加载，避免播放时出现闪烁或卡顿
- 树的主体（树干、树枝、已有树叶）为静态SVG，新生长部分通过CSS animation叠加
- 动画执行期间主线程占用不超过50ms/帧，确保在低端设备上流畅运行

### 四、边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 用户离线时触发事件 | 事件写入本地队列，联网后批量同步并播放动画 |
| 用户快速连续触发多个事件 | 动画排队播放，不做堆叠或跳过，用户可点击屏幕加速当前动画 |
| 用户在动画播放中退出页面 | 动画中断，已触发但未播放的事件标记为"待播放"，下次进入成长树页面时补播 |
| 用户更换设备 | 事件记录基于服务端数据，新设备登录后根据未播放事件列表依次补播（可一键跳过） |
| 成长树页面首次加载 | 加载完成后，按时间顺序快速补播所有未播放动画（每个缩短为0.3秒），超过10个则显示"跳过动画"按钮 |

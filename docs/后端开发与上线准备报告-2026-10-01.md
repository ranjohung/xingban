# 后端开发与上线准备报告（2026-10-01）

## 结论

星伴必须部署后端。儿童档案、行为与心理健康观察、危机记录、周报、专业分享和审计均涉及账号隔离与敏感数据，不能以 GitHub Pages、浏览器本地存储或演示数据作为正式实现。

仓库已有 Express + MySQL 后端及内存开发存储。本轮没有重写已有知识库开发成果，而是在其上补齐部署与接口缺口。

## 正式上线仍需外部资源

代码已经具备部署入口，但 GitHub Pages 只能托管静态前端，不能运行 Express/MySQL。正式上线仍需：

1. 一台支持 Node.js 容器的服务（或云函数）和独立 MySQL 8 数据库。
2. 执行 `backend/config/init_db.sql` 建库，并把密钥放入托管平台环境变量。
3. 给后端绑定 HTTPS 域名，例如 `https://api.example.com`。
4. 推荐通过同站反向代理提供 `/api`；若确需跨站API，必须在HTTPS下显式评估`COOKIE_SAME_SITE=None`、精确CORS来源和第三方Cookie兼容性，不能只修改前端地址。
5. 生产环境不得设置 `USE_MOCK_DB=true` 或 `ALLOW_MOCK_DB=true`；上线前完成备份恢复、日志脱敏、监控告警、数据保留/删除和儿童隐私合规验收。

### 本机数据库说明

2026-10-01 复核发现本机已有的 `xingban` 数据库属于历史 Prisma/Next.js 实现，表名和数据模型与当前 Express API 不一致。为避免覆盖原数据，当前后端使用独立数据库 `xingban_api`；原 `xingban` 数据库保持不变。正式迁移前不得把两套表直接混合，需单独编写、演练并核对数据迁移脚本。

在真实后端域名、数据库和密钥尚未配置前，GitHub Pages 仍只能作为体验版，不应宣称账号数据、分享或反馈已正式持久化。

## 本机开发运行状态

- MySQL：`127.0.0.1:3306`，业务库 `xingban_api`；应用使用最小权限账号，不使用root运行服务。
- Memurai：`127.0.0.1:6379`，通过 `REDIS_URL` 接入认证与知识问答限流。
- 后端：进入 `backend` 执行 `npm start`，随后访问 `/api/health/ready`；只有同时看到 `database=mysql` 和 `cache=redis` 才表示本机两项基础设施均已接入。
- `backend/.env` 仅供本机且已被Git忽略；仓库只提交无密钥的 `.env.example`。生产环境必须重新生成密钥，不能复制本机配置。
- Redis/Memurai在当前实现中属于可降级的限流缓存，短时故障不会阻断核心业务；MySQL属于持久化必需项，未就绪时健康检查返回503。

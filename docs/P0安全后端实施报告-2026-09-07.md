# P0安全后端实施报告

> 日期：2026-09-07
> 范围：敏感数据、所有权、授权分享、访问审计、Express安全基线

## 已实现

- 新增 `sensitive_records`：安全计划、心理健康档案、防走失预案和医疗事件以 AES-256-GCM 密文保存；IV与认证标签独立存储，密钥只从环境变量读取。
- 对外资源ID使用UUID，避免暴露自增数量和可枚举地址。
- `GET/PUT/DELETE /api/sensitive/record/:kind/:childId` 在操作前验证当前用户拥有对应儿童档案。
- 新增 `data_shares`：分享令牌仅保存SHA-256摘要，支持最小范围、1/7/30天有效期和撤销时间。
- 新增 `audit_logs`：记录行为人、角色、动作、资源、结果、请求ID和最小化元数据。
- Express关闭技术指纹，增加请求ID、安全响应头、1MB JSON限制、64KB表单限制和明确CORS白名单。
- API响应使用`default-src 'none'`、禁止frame/base/form的CSP；生产HTTPS响应增加一年HSTS。静态体验页已启用过渡CSP，禁止对象、框架、非白名单连接，并修复搜索、儿童档案和防走失预案的已确认回显注入点。
- 认证验证HS256、有效用户ID、允许角色和唯一`jti`；JWT密钥不足32字符时拒绝服务。生产只接受HttpOnly会话Cookie，不返回也不接受Bearer令牌；Bearer仅在非生产受控测试中兼容。
- 注册密码要求8—72位；登录错误不再区分账号不存在与密码错误。
- 固定短信验证码已禁用。只有显式开启开发演示并通过环境变量提供验证码时才可使用，生产环境必须接入真实短信服务。
- 认证接口增加按IP和路径的内存限流；生产多实例部署需迁移到Redis或网关限流。
- JWT签发统一校验至少32字符密钥、固定HS256、默认2小时有效期；密钥缺失时安全失败，不再尝试使用弱配置签发。
- 前端访问令牌和账号会话已取消localStorage持久化，刷新/关闭页面后要求重新登录，并清理旧版遗留凭证。
- 新增“我的授权”查询接口和前端“授权与访问记录”入口，可查看有效、到期、已撤销分享及最近访问审计，并可立即撤销有效授权。
- 新增儿童/账号级数据删除申请：大写确认、活动申请去重、分享优先撤销、本人状态查询与待处理撤销、管理员隔离队列、拒绝说明、事务级联删除和完成审计。账号删除后通用鉴权按请求核验用户存在及角色，旧Cookie/JWT立即失效。
- 新增安全告警表和扫描服务：短时集中越权、敏感数据解密失败及分享撤销失败形成持久告警；仅管理员可查看、确认和解决，证据只保留聚合次数、账号类型和时间窗。可配置周期扫描，管理员也可在安全运营台手动扫描。

## 尚未关闭的P0外部项

1. 儿童精神科/临床心理人员需要对高危流程签字验收。
2. 各部署地区的医院、急诊和援助资源需要负责人、来源、服务时间与定期复核机制。
3. 需要在正式数据库执行迁移，并将 `JWT_SECRET`、`SENSITIVE_DATA_KEY` 放入密钥管理服务，配置轮换和备份恢复。
4. 前端敏感数据仅在 localhost、127.0.0.1 或本地文件演示时允许localStorage降级；正式域名已禁止降级，但上线前仍需端到端确认服务端加密写入、读取、删除和失败提示。
5. 审计日志已有家长本人只读视图，删除工单与安全告警已有管理员权限隔离和处置状态；仍需确定审计留存/脱敏策略、外部通知渠道和异常访问值守排班。
6. 分享创建、所有者列表和撤销已具备；分享接收端必须完成令牌校验、接收者绑定和逐字段范围过滤后才能正式开放。
7. 内存限流在多实例环境不共享，生产部署需Redis/网关实现。
8. 首轮DOM XSS整改、静态及Chromium恶意载荷回归已完成；7,000余行主脚本与两段样式已外置，`script-src`只允许同源且页面没有内联脚本块。仍有342个事件属性（323个点击）和132个动态HTML写入点；必须将事件改为监听器并移除`script-src-attr 'unsafe-inline'`后才能启用严格CSP。
9. 已迁移为生产HttpOnly、Secure、SameSite会话Cookie；独立可读CSRF Cookie必须与`X-CSRF-Token`请求头恒定时间匹配。退出和改密把JWT `jti`写入Redis/Memurai撤销表并清除Cookie；生产Bearer被拒绝。正式环境仍须通过HTTPS同站反向代理部署并复核Cookie域和CORS白名单。

## 认证迁移复核（2026-10-02）

- `npm run test:auth`以`NODE_ENV=production`启动隔离服务，验证JSON不返回令牌、会话Cookie包含HttpOnly/Secure/SameSite=Strict、CSRF Cookie不设HttpOnly、无CSRF写入返回403、合法写入成功、Bearer返回401、退出后旧Cookie重放返回401。
- 真实MySQL移动验收将`RETURN_BEARER_TOKEN=false`，浏览器脚本确认`getToken()`为空，仍可完成家长和专业账号登录、24功能区、计划确认与退出；CSRF Cookie存在且测试账号全部清理。
- 本机预览统一使用`127.0.0.1`访问前后端，避免`localhost`与IP不属于同一站点导致Cookie/CSRF失效。

## 验证

- `scripts/security_p0_test.js` 验证随机IV、认证解密、篡改失败、UUID、分享令牌和明文不进入密文载荷。
- 后端全部JavaScript文件执行语法检查。
- SQL迁移包含唯一约束、所有者索引、资源索引和外键。
- `npm run test:deletion`在真实MySQL验证儿童删除申请撤销后数据保留，以及账号删除经管理员处理后用户、儿童、分享级联消失；工单保留为`completed`且申请人外键清空，完成审计存在，旧会话返回401。
- `npm run test:alerts`在真实MySQL验证三类规则、普通账号403、证据最小化、管理员确认/解决和审计；测试数据自动清理。

当前结论：P0工程基础已建立，但在数据库迁移、密钥托管、前端联调及三项外部验收完成前，仍不能标记为生产可用。
